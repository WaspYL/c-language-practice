1 嵌入式基础概念

先搞懂单片机到底是什么

1.1 单片机（MCU）是什么

单片机就是一台塞在指甲盖大小芯片里的小电脑，里面有CPU（算东西）、RAM（临时内存）、Flash（存代码）、各种外设（GPIO、串口、I2C、网口）。

比喻：电脑是台式机，单片机就是把这些全做进一个芯片里，没有屏幕键盘，靠引脚和外界说话。

CH32V307参数：RISC-V内核，144MHz，256KB Flash，64KB RAM，带10M以太网PHY。

1.2 寄存器是什么

寄存器是芯片内部的特殊内存地址。你往某个地址写0或1就能控制硬件，从某个地址读就能知道硬件状态。

比喻：寄存器就像一排开关灯的按钮，每个按钮有编号（地址）。按编号0x0400，PA0就输出高电平。
库函数（GPIO_WriteBit等）就是帮你操作这些寄存器地址，不用你自己记地址。

1.3 位、字节、十六进制

位(bit)：最小单位，0或1。字节(Byte)：8个位。十六进制(0x)：4个二进制位用1个十六进制位表示。

二进制十六进制十进制含义
000000000x000全灭
111111110xFF255全亮
000000010x011最低位是1
为什么代码里到处是0x？一个字节8位写成二进制要8个0/1，写十六进制只要2位，一眼看出哪几位是1。

1.4 上拉/下拉电阻

引脚悬空时电平不确定会乱跳。上拉：通过电阻接3.3V，默认高电平，按键按下接地变低。下拉：通过电阻接地，默认低电平。

比喻：上拉就像门弹簧，默认门关着（高电平），你按一下（接地）门开了（低电平）。

1.5 为什么要开时钟

芯片为了省电，默认所有外设都是断电的。不开时钟，你怎么配引脚都没反应！这是新手最常踩的坑。
比喻：时钟=外设的电源开关。你不插电，台灯开关再怎么按灯也不亮。

2 GPIO 深入理解

引脚到底怎么控制

2.1 GPIO三步曲

  • 开时钟：RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);
  • 配引脚：GPIO_InitStruct填引脚号、模式、速度
  • 初始化：GPIO_Init(GPIOA, &GPIO_InitStruct);

2.2 推挽 vs 开漏

推挽输出：芯片内部有两个开关，能主动接3.3V或GND，驱动能力强。

开漏输出：只能接GND（拉低），不能主动接3.3V，高电平靠外部电阻。

I2C必须用开漏！因为SDA线多个设备共用，如果两个设备一个推挽输出1一个输出0，会短路烧芯片。开漏只能拉低，不会短路。

2.3 八种工作模式

模式通俗解释用在哪
Out_PP 推挽输出主动高低电平LED、蜂鸣器
Out_OD 开漏输出只能拉低，外部上拉I2C
IPU 上拉输入默认高，按下变低按键
IPD 下拉输入默认低外部信号
AF_PP 复用推挽引脚交给外设串口TX、ETH

2.4 操作引脚的函数

C
GPIO_SetBits(GPIOA, GPIO_Pin_0);    // PA0高电平
GPIO_ResetBits(GPIOA, GPIO_Pin_0);  // PA0低电平
GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_0); // 读PA0

3 串口通信 USART

芯片和电脑怎么对话

3.1 串口是什么

串口是最简单的通信：一根线发(TX)，一根线收(RX)，按约定速度(波特率)逐位传字符。

比喻：像发电报，按固定速度"滴-答-滴-答"发比特，双方要约定好速度才能听懂。
参数值
波特率115200
数据位8
停止位1
校验无

3.2 为什么TX接RX

芯片的TX(发)要接电脑的RX(收)，就像你的嘴要对着对方的耳朵。我们只用PA9(TX)，因为只要芯片发给电脑。

3.3 为什么不用printf

MRS工程的debug.c已经写了_write函数，你再写一个会报redefinition冲突。所以自己写三个函数：
函数作用关系
SendChar(c)发一个字节最底层
SendString(s)发一串文字循环调SendChar
SendNum(n)发数字转成字符串再发

4 I2C通信协议

两根线接一堆设备

4.1 I2C vs SPI vs UART

协议线数速度特点用在哪
UART2慢点对点串口调试
I2C2中多设备，地址区分OLED、ADXL345
SPI4快高速，每设备片选Flash、屏幕

4.2 I2C时序

信号SCLSDA含义
起始高高变低"开始说话"
数据高电平时读SCL低时改变按节拍发8位
应答第9脉冲从机拉低"收到了"
停止高低变高"说完了"
关键规则：SCL高电平时SDA绝对不能变！否则会被误认为起始/停止。只有SCL拉低后SDA才能变。

4.3 软件I2C vs 硬件I2C

软件I2C：用普通GPIO自己模拟时序。任意引脚，灵活，但占CPU。

硬件I2C：芯片内部专门外设自动发时序。快，但引脚固定。

我们用软件I2C，因为引脚灵活，而且你亲手控制每根线高低，能真正理解I2C在干嘛。

4.4 OLED原理

SSD1306，128x64像素，分8页每页8行。发一个字节=控制一列8个点。

命令作用
0xB0+page选第几页(0~7)
发0xFF这列8个点全亮
发0x00这列8个点全灭
注意：本项目OLED因接线短路已烧坏，待购新模块。

5 ADXL345 加速度计

怎么感知震动

5.1 它怎么测加速度

MEMS加速度计内部有微小"质量块"，加速度变化时质量块位移，电容变化转成数字值。

比喻：就像坐车加速会被推向后座。芯片内部有个小质量块，感知三个方向的"推力"。

平放时Z轴约等于1g(重力)，X、Y约等于0。倾斜时三轴数值都会变。

5.2 关键寄存器

寄存器地址操作作用
DEVID0x00读应读到229(0xE5)，验证芯片活着
POWER_CTL0x2D写0x08上电测量模式
DATA_FORMAT0x31写0x00正负2g量程
DATAX~Z0x32~0x37读6字节XYZ原始数据

5.3 连续读技巧 |0x40

C
ADXL_WriteReg(0x32 | 0x40);  // |0x40=读完自动加地址
xl = ADXL_ReadReg();  // X低字节
xh = ADXL_ReadReg();  // X高字节
int16_t ax = (xh << 8) | xl; // 拼成16位
为什么要|0x40？不写的话每读一个字节都要重新发地址。写了之后芯片自动每次读完地址+1，连续读6字节一次搞定。

5.4 震动检测算法

思路：比较相邻两次读数的差。静止时变化小，震动时变化大。

C
int shake = abs(ax-lastX) + abs(ay-lastY) + abs(az-lastZ);
lastX=ax; lastY=ay; lastZ=az;

if(shake < 10)      level=0; // 静止
else if(shake < 50) level=1; // 轻微
else               level=2; // 强烈报警

6 以太网TCP

板子怎么上网

6.1 网络概念

概念比喻我们的值
IP地址门牌号板子192.168.1.100，电脑192.168.1.10
端口号房间号8888
子网掩码区范围255.255.255.0
两个IP都要192.168.1.x同网段才能直连通信，不同网段需要路由器。

6.2 客户端 vs 服务器

服务器：先开门等客人。电脑是服务器，Python脚本先运行监听8888。

客户端：主动敲门。板子是客户端，上电后主动连电脑。

比喻：服务器=餐厅先开门营业，客户端=顾客找上门。必须先开门才能接客，所以Python要先运行。

6.3 WCHNET库

TCP协议极其复杂（IP分包、MAC寻址、三次握手、超时重传），WCH封装成NetLib，你只调函数。
函数作用
ETH_LibInit()启动以太网
WCHNET_CreateTcpSocket()创建TCP连接
WCHNET_MainTask()网络心跳，必须while里一直调
WCHNET_SocketSend()发数据
WCHNET_MainTask()必须一直调！不调它就收不到数据、连接会断。

6.4 数据协议

板子每200ms发一行：

协议
X,Y,Z,shake,level\n

例如：-164,-1,-1,82,2。level: 0=静止 1=轻微 2=强烈。

6.5 遇到新外设怎么办

核心套路：MRS新建工程没有这个外设库 → 去WCH官网下EVT包 → 在EXAM目录找最接近的示例 → 直接用那个工程改main.c。不要从零造轮子！

7 面包板与安全

接线不短路才是王道

7.1 面包板怎么连通

MB-102中间5个孔连通（同列），两边红蓝轨整行连通。红轨=电源，蓝轨=GND。

7.2 为什么需要面包板电源

核心板GND只有2个不够用。面包板电源模块插上后，红轨=3.3V，蓝轨=GND，所有模块从面包板取电。

7.3 安全操作

所有接线改动必须先断电！带电插拔可能短路烧芯片。之前OLED就是接ADXL345时短路烧坏的。
  • 接线：先接信号，最后接电源
  • 拆线：先断电源，再拔信号
  • 3.3V和GND绝对不能碰一起

7.4 关机拔线顺序

  1. 关PowerShell窗口
  2. 拔Type-C电源线（先断电）
  3. 拔YD-LINK的USB
  4. 网线可拔可留

9 库函数记忆法

函数名太长？其实有规律

9.1 函数命名规律

WCH库函数名是有规律的，看懂规律就不用死记：

规律
GPIO_WriteBit(GPIOA, GPIO_Pin_0, Bit_SET)
 │     │      │       │          │
 外设  动作   哪个端口  哪个引脚    写什么值
  • 第一段：外设名（GPIO/USART/RCC/I2C）
  • 第二段：动作（Init初始化/SetBits置高/ResetBits置低/Read读/Send发）
  • 参数顺序：先选外设，再选引脚/通道，再给值
比喻：就像"打开客厅的灯"——先选房间(客厅)，再选物品(灯)，再做动作(打开)。

9.2 看到函数名能猜出意思

函数名拆词理解作用
RCC_APB2PeriphClockCmdRCC + APB2 + 外设 + 时钟 + 命令开APB2总线上的外设时钟
GPIO_InitGPIO + 初始化按结构体配置引脚
GPIO_SetBitsGPIO + 设置位引脚输出高电平
GPIO_ResetBitsGPIO + 复位位引脚输出低电平
GPIO_ReadInputDataBitGPIO + 读 + 输入 + 数据 + 位读引脚电平
USART_SendData串口 + 发送 + 数据串口发一个字节
USART_GetFlagStatus串口 + 获取 + 标志 + 状态查串口状态
记不住就查芯片手册或工程里的头文件！不用全背，常用的写多了自然记住。头文件ch32v30x_gpio.h里有所有函数声明，点进去就能看。

9.3 引脚号怎么记

GPIO_Pin_0到GPIO_Pin_15对应第0到第15脚，就是二进制：

引脚号宏定义二进制
第0脚GPIO_Pin_00001
第1脚GPIO_Pin_10010
第5脚GPIO_Pin_50100000
同时选0和5GPIO_Pin_0 | GPIO_Pin_5按位或

10 常用库函数大全

不用全背，知道有这些东西就行

10.1 RCC 时钟（第一步必调）

函数作用什么时候用
RCC_APB2PeriphClockCmd(APB2Periph_GPIOA, ENABLE)开GPIOA时钟用PA口之前
RCC_APB2PeriphClockCmd(APB2Periph_GPIOB, ENABLE)开GPIOB时钟用PB口之前
RCC_APB2PeriphClockCmd(APB2Periph_USART1, ENABLE)开串口1时钟用串口之前
口诀：用哪个外设先开哪个时钟。GPIOA/GPIOB/GPIOC在APB2总线上，USART1也在APB2。

10.2 GPIO 输出

函数作用
GPIO_SetBits(GPIOx, GPIO_Pin_n)引脚输出高电平(3.3V)
GPIO_ResetBits(GPIOx, GPIO_Pin_n)引脚输出低电平(0V)
GPIO_WriteBit(GPIOx, GPIO_Pin_n, Bit_SET/RESET)上面两个的合体
GPIO_Write(GPIOx, 0xFF00)一次写整个16位端口

10.3 GPIO 输入

函数作用
GPIO_ReadInputDataBit(GPIOx, GPIO_Pin_n)读单个引脚电平，返回0或1
GPIO_ReadInputData(GPIOx)读整个端口16位

10.4 USART 串口

函数作用
USART_Init(USART1, &initstruct)按结构体配串口参数
USART_Cmd(USART1, ENABLE)使能串口
USART_SendData(USART1, byte)发一个字节
USART_GetFlagStatus(USART1, USART_FLAG_TC)查发送完成没有
USART_ReceiveData(USART1)读收到的一个字节
TC标志：Transmission Complete，上一个字节发完了才能发下一个。

10.5 延时

函数作用
Delay_Ms(1000)延时1000毫秒=1秒
Delay_Us(10)延时10微秒
Delay是死等（阻塞），CPU啥也不干就在那等。以后学了定时器中断就不用Delay了。

10.6 你自己写的函数（比库函数还重要）

函数作用什么时候用
USART1_SendChar(c)串口发一个字底层
USART1_SendString(s)串口发文字打印调试信息
USART1_SendNum(n)串口发数字打印传感器值
I2C_Start/Stop/SendByte软件I2C时序和OLED/ADXL通信
ADXL_ReadXYZ()读加速度获取震动数据
OLED_ShowString()OLED显示文字屏幕输出
Beep_On/Off()蜂鸣器响/停报警
为什么要自己写函数？主函数main里不要堆一堆底层操作。把"读ADXL"包成ADXL_ReadXYZ()，main里只要调这个函数就行。这叫模块化，改一个地方不影响其他。

11 独立做项目思路

以后拿到新项目怎么下手

11.1 从需求到成品的完整流程

项目流程
第1步：搞清楚要做什么     → 需求分析
第2步：列出来需要什么硬件   → 选型（用什么传感器、什么通信）
第3步：画接线图           → 每个模块接哪个引脚
第4步：分模块写代码        → 一个模块一个模块验证
第5步：整合调试           → 全放一起跑
第6步：包装演示           → 外壳、文档、答辩

11.2 分模块验证（最重要的心法）

不要一上来就把所有代码写完！一个模块通了再加下一个：

顺序模块验证标准通了再加下一个
1LED闪烁灯一闪一闪说明芯片和下载器OK
2串口打印电脑能看到文字说明调试通道OK
3读传感器ID串口打印出正确ID说明I2C通信OK
4读传感器数据串口打印XYZ值说明数据采集OK
5加算法shake值随震动变化说明逻辑OK
6加执行器蜂鸣器响说明输出OK
7加通信数据传到电脑说明联网OK
为什么要这样？一次写完全部代码，出了bug你根本不知道是哪个模块的问题。一个一个来，出了错就是新加的那个模块的问题。

11.3 怎么查新资料

  1. 芯片手册：WCH官网下CH32V307参考手册，有所有寄存器说明
  2. EVT示例包：D盘那个EVT文件夹，每个外设都有示例代码
  3. 头文件：Peripheral/inc里，点进去看函数声明和注释
  4. 串口打印：不确定的值全打印出来看，比猜快10倍

11.4 代码结构怎么组织

一个好的工程应该长这样：

目录结构
User/
  main.c          ← 主函数，只做调度
  adxl345.c/h     ← ADXL驱动（读数据）
  oled.c/h        ← OLED驱动（显示）
  beep.c/h        ← 蜂鸣器控制
  sensor.c/h      ← 算法（震动检测）
Core/             ← 系统文件，不动
Peripheral/       ← 库文件，不动
原则：main.c里只写"做什么"，不写"怎么做"。怎么做都封装在各个模块的.c文件里。以后换传感器，只改adxl345.c，main.c一行不动。

11.5 项目逻辑思维训练

拿到一个新项目，按这个思路想：

  • 输入是什么？传感器（ADXL345）、按键、串口
  • 输出是什么？LED、蜂鸣器、屏幕、网络
  • 中间怎么处理？读数据→算算法→判断→执行动作
  • 怎么调试？用串口把中间值全打出来
比喻：做项目就像做菜。输入=食材(传感器)，输出=菜(执行器)，中间处理=炒菜(算法)，调试=尝味道(串口打印)。

项目输入输出核心算法
